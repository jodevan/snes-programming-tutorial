Appendix: SNES Address & Register Map

Appendix: SNES Address & Register Map

A single-page reference for every hardware address this course actually touches, organized the way the lessons introduced it rather than dumped alphabetically. Cross-checked against the same code shown in each lesson, not transcribed from memory — if a value here ever disagrees with a lesson’s own code, the lesson’s code is correct and this page has a bug worth reporting.

Three address spaces, not one

It’s easy to assume “the address space” is one thing. This course actually works across three separate ones, and mixing them up is a real source of confusion:

Space Who reads/writes it Covered in
65816 CPU space The main CPU — everything through Lesson 12 Lesson 3
SPC700 / ARAM space The sound co-processor’s own 64 KB RAM, reachable only through 4 mail-slot bytes Lesson 13
DSP register space The audio chip’s 128 one-byte registers, reachable only through the SPC700 boot ROM’s $00F2 trick Lesson 13

Every table below is 65816 CPU space unless its heading says otherwise.

Memory map: sizes & boundaries

Six fixed-size memory pools this course touches, each a separate physical resource — knowing the size of each one explains why VRAM comfortably fits a course’s worth of tiles and tilemaps, why OAM caps out at 128 sprites, and why a palette can’t hold more than 256 colors.

Region Total size Address range Holds Lesson
WRAM 128 KB $7E0000-$7FFFFF (full chip); first 8 KB mirrored at $0000-$1FFF in every bank’s low page Variables, the stack, general-purpose scratch Lesson 3
VRAM 64 KB word address $0000-$7FFF, reached via VMADDL/VMADDH Tile (character) bitmap data and tilemaps — this course’s tiles and BG3 tilemap both live here, at addresses you choose Lesson 5, Lesson 6
CGRAM 512 bytes index $00-$FF via CGADD (each index = 2 bytes) 256 colors, organized as 16 palettes of 16 colors, 15-bit color each Lesson 4
OAM 544 bytes low table: byte $000-$1FF (512 bytes); high table: byte $200-$21F (32 bytes), via OAMADDL/OAMADDH Up to 128 sprites — X/Y/tile/attributes in the low table (4 bytes each), size + X-high-bit in the high table (2 bits each) Lesson 10
ARAM (SPC700 RAM) 64 KB $0000-$FFFF on the SPC700’s own bus — not reachable directly from the 65816 Sound driver code, sample data, echo buffer, loaded byte-by-byte through the 4 APU mail-slot ports Lesson 13
ROM (LoROM mapping) up to 4 MB addressable (this course’s own ROMs use far less) banks $00-$7D and $80-$FF, each exposing 32 KB at $8000-$FFFF Program code, the header & vectors, and any other ROM data Lesson 1, Lesson 3

VRAM, CGRAM, and OAM aren’t part of the 65816’s own address space — they’re separate chips on the PPU side, reachable only through the port registers documented below ($2115-$2119 for VRAM, $2121-$2122 for CGRAM, $2101-$2104 for OAM).

ROM header & vectors — $00:FFC0–$00:FFFF

Audio: APU ports (65816 side) — $2140-$2143

Address Register Purpose Lesson
$2140-$2143 APUIO0-APUIO3 Four one-byte mail-slot ports to the SPC700 — the only connection between the two CPUs Lesson 13

The SPC700 sees the same four ports at $00F4-$00F7 on its own side — same bytes, different address, because it’s a different CPU with a different memory map entirely.

Audio: DSP registers (a separate 128-register space, reached via $00F2)

Not part of the 65816’s memory map at all — these are written by targeting SPC upload address $00F2 with the boot ROM’s manual-DSP trick, one (register, value) pair per write_dsp call. Register numbers below are for voice 0; Lesson 14 reaches voice n by adding n * $10 to each per-voice register number.

Register Name Purpose Lesson
$4C KON Key-on — one bit per voice (0-7) Lesson 13
$5C KOFF Key-off — one bit per voice; needed before a fresh KON to restart an already-playing voice Lesson 13, Lesson 14
$6C FLG Global flags (echo-buffer write protect, etc.) Lesson 13
$5D DIR Sample directory’s ARAM page Lesson 13
$0C/$1C MVOLL/MVOLR Master volume, left/right Lesson 13
$00/$01 VOLL/VOLR (voice 0) Per-voice volume, left/right Lesson 13
$02/$03 PITCHL/PITCHH (voice 0) Playback rate — $1000 plays a sample at its recorded pitch Lesson 13
$04 SRCN (voice 0) Which sample-directory entry this voice plays Lesson 13
$05/$06 ADSR1/ADSR2 (voice 0) Volume envelope: attack/decay (ADSR1), sustain level/rate (ADSR2) Lesson 13, Lesson 14 exercises

What’s deliberately not here

This page is hardware facts — SNES-defined registers and memory regions that stay the same no matter what ROM you write. It doesn’t include this course’s own direct-page variable choices (sprite_x, scroll_lo, wall_x, and so on, first assigned in Lesson 9 and Lesson 11) — those are this tutorial’s own example code, not SNES architecture, and a different project is free to lay them out differently.
